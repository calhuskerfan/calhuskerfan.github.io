> Connecting SRQC to a Message Queue Service

This post extends the queue consumer pattern [discussed here]({% post_url 2025-09-28-SQRC %}) to utilize a message brokering service.  This implementation is using [RabbitMQ](https://www.rabbitmq.com/).

Two queues will be used, one for inbound message handling and one for outbound message handling.  These queues will be operating as [Message Channels](https://www.enterpriseintegrationpatterns.com/patterns/messaging/MessageChannel.html) to facilitate asynchronous communication between the  components.  One channel is reponsible for the producer to processor inbound path and the other is responsible for the processor outbound to consumer.

![image]({{ site.baseurl }}/assets/images/srloader-part2.drawio.png)

## Operation

The system consists of the following components

| Component | Description |
|-----------|-------------|
| Message Producer | Console application that produces a configurable number of messages and Publishes them to the Inbound Queue
| Inbound Queue | A typical inbound queue in a Message Orientated Middleware (MOM) style application.  A RabbitMQ Queue in this system.|
| Message Processor | Component that receives Messages from the Inbound Queue, handles the SRQC libraries as described [here]({% post_url 2025-09-28-SQRC %}) and Publishes the results to the Outbound Queue.
| Outbound Queue | A typical outbound queue in a Message Orientated Middleware (MOM) style application.  A RabbitMQ Queue in this system.
| Message Consumer | Responsible for Receiving and Handling Messages placed in the Outbound Queue


### RabbitMQ Implementation Notes

The use of RabbitMQ is failry straighforward in this demonstration and relies mostly on the defaults.  There is however one component that deserves some attention, and that is the use of the [Consumer Prefetch](https://www.rabbitmq.com/docs/consumer-prefetch) count.

The consumer prefetch count in RabbitMQ controls the maximum number of unacknowledged messages a consumer can receive from RabbitMQ at any given time.  In this demonstration is set at the channel level with a call to the BasicQosAsync() function.

```csharp
    await channel.BasicQosAsync(0, _channelReader.PrefetchCount, false);
```

Since we are using an async, event driven, consumer the prefetch count is used to limit the 'inflight' messages a consumer needs to handle.  This limits resources required and reduces messages that are 'at risk' during the handling process.
